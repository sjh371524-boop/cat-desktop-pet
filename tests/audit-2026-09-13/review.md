# Codex Cat 当前体验审查（2026-09-13）

## 审查范围

本次以当前构建重新渲染的桌宠快照、当前源码与本地设置为依据，覆盖默认站立、拖动、舔爪、摸摸、哄睡、睡眠、互动气泡和算数机。未进行长时间真人使用测试、键盘/屏幕阅读器测试或多显示器实机测试，因此不把截图结论表述为完整可访问性认证。

## 总体判断

当前版本已经不是“缺功能”的桌宠：角色身份、异瞳、鼠标视线、拖动、定时待机、睡眠、互动气泡、天气、缩放、托盘和离线算数均已形成闭环。下一阶段最值得投入的不是继续堆菜单，而是统一角色模型和动作素材、解决整帧交叉淡化产生的重影、增加可视化设置入口，并降低后台常驻成本。

## 流程步骤与健康度

1. 默认站立与鼠标注视 — 良好。角色轮廓清楚、异瞳辨识度高，正面身份稳定；但尾巴边缘和身体边缘的像素锐度仍需在实际非整数缩放下观察。
2. 鼠标拖动与侧身步态 — 需优先优化。当前快照可见后脚灰蓝残影以及前脚附近粉色碎片，侧身模型与正面模型的体型、毛量和头身比例也不完全一致。
3. 定时舔爪与待机动作 — 需优先优化。舔爪中间态可见整只猫、尾巴和前爪的双重轮廓；这是整帧透明度混合在肢体位移较大时的典型副作用。
4. 摸摸与哄睡 — 基本可用，视觉一致性偏弱。触摸反馈完整，但手掌比像素猫更平滑、更写实，像素密度、描边和光照语言不一致；手掌与头/身体接触处缺少统一遮挡关系。
5. 睡眠与叫醒入口 — 良好。蜷缩轮廓、闭眼、包尾和 Zzz 的信息表达清楚，睡眠气泡能把“哄睡它”替换为“叫醒它”。
6. 普通互动气泡 — 功能完整，层级需要收敛。所有卡片已在云朵内部，但高亮蓝色外发光、深蓝边框、淡黄卡片和红橙绿三个圆同时争夺注意力；在当前 0.6144 缩放下，天气文字约 7.7 DIP、保持清醒文字约 7.1 DIP，可读性不足。
7. 算数机 — 功能健康、风格割裂。按键分组和运算层级清楚，但深色工业面板与柔和云朵、像素猫像是两个产品；气泡和计算器同时出现时占用桌面面积较大。

## 已确认的优势

- 异瞳身份、三花色块、粉鼻和橘色尾尖已形成可辨认的角色特征。
- 状态调度器处理了定时冲突、亮屏计时、自动睡眠与保持清醒规则，逻辑完整度高。
- 天气具备缓存、失败提示、TLS 处理和动态图标，不会无限显示“加载中”。
- 算数机完全离线，功能边界清楚，不再依赖浏览器、账号或 API。
- 当前快照验证会检查尾根、哄睡衔接、气泡越界、天气图标和异瞳等关键约束。

## 最高影响问题

### P0：建立统一角色模型表，再重做问题最大的动作帧

先固定正面、左右 3/4、左右侧面、坐姿和蜷缩睡姿的头顶、耳根、眼中心、肩线、胸宽、四爪落点、臀部和尾根坐标。所有新帧必须从这套模型表出发。优先重做拖动和舔爪，不要继续通过整帧交叉淡化掩盖两张差异很大的姿势。

建议每个大动作至少提供 6–10 张真正的中间姿势；身体变化小的部位可以分层，四肢和嘴部位移较大时应使用逐帧关键姿势。这样比再次生成一条风格不同的独立尾巴更符合当前角色。

### P0：消除整帧双重轮廓

`DrawFrameBlend` 会同时降低前一整帧透明度并提高后一整帧透明度。它适合眨眼和轻微呼吸，不适合走路、舔爪、趴下等肢体跨越较大的动作。应按动作类型切换策略：小变化继续混合，大变化使用定时逐帧、局部部件插值或额外中间帧。

### P1：让互动 UI 保持最小可读尺寸

桌宠可以继续按 20% 放缩，但气泡和计算器不应在低于约 0.85 UI 比例后继续同步缩小文字与点击目标。建议桌宠缩放和 UI 缩放分离：位置、气泡方向仍跟随猫咪，内容区域设置最小宽度和最小字号。保留“跟随缩放”的视觉关系，同时避免 7–9 DIP 的文字。

### P1：增加一个真正的设置面板

当前设置只能通过 JSON 或分散的圆形按钮修改。建议把猫咪名字、城市/自动定位、缩放、始终置顶、启动位置、开机启动、待机频率、自动睡眠、降低动画、锁定位置和恢复默认值集中到一个猫爪样式设置面板。位置检测必须请求系统权限，并保留手动城市回退。

### P1：降低常驻刷新成本

当前动画计时器固定约 16ms 刷新，即使窗口隐藏或屏幕关闭也继续进入更新函数。建议动作时 60 FPS、普通站立 20–30 FPS、隐藏或熄屏时暂停视觉刷新，只保留必要的低频计时。这样比继续压缩 PNG 更能降低长期 CPU 与耗电。

### P1：补视觉回归测试

现有测试能确认文件存在、关键区域不变和边界衔接，但拖动碎片、舔爪重影等明显视觉问题仍可通过。建议为默认、拖动、舔爪、摸摸、哄睡、睡眠、气泡和计算器保留黄金快照，并进行感知差异比较；对手—耳朵、尾根—臀部、脚—地面等接触区增加局部阈值。

## 适合新增的内容

1. **身体分区互动**：点击头、背和尾巴触发不同的小反应，不增加气泡按钮。头部享受，背部伸懒腰，尾巴被碰时回头看；比增加更多菜单更像真实猫。
2. **逗猫棒模式**：复用已有鼠标位置追踪，进入后猫咪先盯住光点，再做一次短距离扑抓。需要专用蹲伏、蓄力、扑抓和收势帧，并设置冷却时间，不能直接移动整只站立图。
3. **时间/天气微反应**：早晨伸展、夜间更容易困、雨天偶尔抖耳或看天气。只作为低频动画，不新增常驻信息卡。
4. **位置记忆与锁定**：拖动结束保存所在显示器和相对位置；增加“锁定位置/暂时穿透点击”，避免误拖。多显示器变化时重新夹取到可见工作区。
5. **轻量亲密反馈**：不要做复杂数值养成；可以根据当天互动次数，在摸摸结束后偶尔增加呼噜文字、贴近屏幕边缘坐下或慢眨眼。反馈应可关闭，也不应制造任务压力。
6. **发布形态**：增加猫咪托盘图标、版本号、开机启动开关和免编译启动包。当前启动脚本每次无人运行时都会重新编译，更像开发工程而不是完成度高的日常桌宠。

## 不建议现在新增

- 暂时不要恢复浏览器 ChatGPT 套壳、API 聊天或更多在线服务。它们会把桌宠重新变成复杂工具，并引入账号、费用、会话和浏览器生命周期问题。
- 暂时不要继续向云朵内部增加新按钮。当前已经接近信息密度上限，新增互动更适合通过点击猫咪身体或二级设置面板承载。
- 不建议默认加入声音。若以后加入呼噜声，应默认关闭、独立音量控制，并遵守系统勿扰状态。
- 不建议再次用单张新生成尾巴替换所有姿势。更稳妥的是基于统一模型表手工制作少量尾巴关键帧，并逐帧检查臀部接缝。

## 代码与资源维护风险

- `assets/character/manifest.json` 仍记录已经删除的 `FeedingFish` 行为，`assets/ui/feeding/fish-v1-imagegen.png` 也仍存在；运行代码没有喂鱼逻辑，但这些残留可能误导后续维护或被重新打包。
- `AppSettings.Load()` 在配置损坏时直接回退默认值，没有向用户说明；建议保留损坏文件并显示一次可恢复提示。
- 当前没有保存猫咪最后所在位置，只保存缩放等设置；重启后会重新落到右下角或屏幕中央。
- 自定义按钮模板没有明显的悬停、按下与键盘焦点状态；鼠标点击虽可用，但键盘可达性和状态反馈需要实机测试。
