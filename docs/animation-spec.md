# 原型猫咪动作素材规范

## 不可改变的视觉基准

正式素材必须以最新异瞳基准 `template-input/pixel-calico-heterochromia.png`（运行素材副本 `assets/character/reference/pixel-calico.png`）为首要角色参考。照片参考为 `template-input/cat-reference.png`。正面画面左眼保留黄绿色，右眼淡蓝；对应猫咪解剖学左眼淡蓝，转向、歪头、眨眼和醒来不得交换眼色。原始 `猫.jpg` 及 `source-art/pre-heterochromia` 只作来源档案，不能用于恢复旧眼色。保留脸型、耳朵、鼻嘴、身体比例、尾巴、毛色分区、纹理、材质和整体气质。导出真实透明 Alpha PNG，禁止棋盘格伪透明或新增配饰。

所有帧采用相同画布和角色缩放比例，面向用户的站立帧是绝对造型基准。脚底基线、身体中心和头部中心在同一动作组内应稳定，避免播放时角色跳动。

## 全局连贯性标准（后续动作同样适用）

- 任意状态变化必须经过 `AnimationTransitionProfile`，禁止在事件处理器中用一张新图直接覆盖旧姿态。普通切换使用 180–240ms，拖动步态与收势的同姿态衔接可缩短至 120ms。
- 缓动统一使用五阶 `smootherstep`；起点和终点的速度、加速度均为零，避免刚开始就冲出或结束时突然刹停。
- 动作内部按连续进度定位相邻两帧，不得四舍五入跳帧。常规大姿态动作只在每个关键帧交界中心使用短融合窗口，以减少双重轮廓；步态、眨眼和转身等小间距帧允许完整连续融合。
- 非循环动作的首帧必须兼容来源状态，末帧必须兼容目标状态。程序会给 `idle_1` 与 `pet` 在内存中补默认站立端点；素材仍应尽量自行提供自然的准备与收势姿态。
- 朝向变化、站立/趴卧、四肢承重变化等大幅动作必须提供真正的中间帧，不能只靠透明度淡入淡出。拖动固定使用 `drag_transition/right` 与 `drag_transition/left` 的独立 4 帧转身桥；松手时反向播放回正。
- 动画被高优先级状态打断时，保留被打断当刻的姿态作为过渡来源，再平滑进入目标状态；不得先闪回默认站立。
- 循环动作的首尾要在脚底基线、身体中心、轮廓、光照和尾巴位置上兼容。后续每加一个状态，都要为其进入、退出和被打断三种情况做预览验收。

## 动作组与关键帧建议

### 全局触发与覆盖规则

自动动画的优先级为：默认五分钟舔爪/第六次特殊睡眠 > 60 秒待机动画1 > 随机摇尾。手动互动与拖动期间不启动新的自动动作。任意自动动画到点但被覆盖时，本次记为未实际完成，同时消费此次触发并重置自己的周期；不增加普通舔爪完成计数，不在冲突结束后补播。只重置实际到点或被中断的动画，不清除尚未到点的其他计时器。

### `TailIdle`（随机摇尾待机）

- 保持当前异瞳三花站立母版，不生成新体型或更换表情；仅尾巴、眨眼以及原有微弱呼吸参与。
- 上次动作完成后随机等待 10–20 秒。动作固定 2 秒，不纳入下一次等待。若被覆盖，本次不播放并从覆盖时重新抽取等待时间。
- 每秒完成一次轻柔上下往返，共两个来回。幅度上限 10 度，各回合首尾缓入缓出。
- 动作 0.96 秒开始眨眼，约 1.04–1.08 秒闭眼，1.28 秒前恢复睁眼；第二次摇尾结束时已经睁开。
- 使用与站立相同的开眼/闭眼帧和独立尾巴层。进出状态走既有平滑过渡；首尾与相同呼吸相位的站立姿态逐像素匹配。

### `stand`

- 面向用户，保持原图同样的普通站立状态。
- 包含细小的胸腹呼吸、毛发高光流动、耳尖轻动和自然眨眼。
- 普通站立增加鼠标目光跟随：由 `PetGazeProfile` 将全桌面鼠标位置换算为相对两眼中心的方向，抵消实际控件缩放、留边及呼吸偏移；5 个逻辑像素内自然回正，远处位移平滑限幅。指数跟随时间常数为 0.09 秒，与帧率无关。
- `PetEyeLayer` 只在 256 像素母版的两个眼内椭圆中重采样原始纹理：左眼中心 `(133.6,76.8)`、半径 `(8.1,8.6)`；右眼中心 `(172.9,76.8)`、半径 `(7.5,8.4)`。位移场上限水平 3.6、垂直 3.2 个源像素，边界固定，透明度、眼外像素和源文件完全不变。后续更换角色布局时必须一同更新眼区标定，不能套用旧坐标到不同脸型。
- 普通眨眼继续使用原闭眼帧，目光层只参与睁眼帧；任何非 `Stand` 状态（包括 `TailIdle`）都使用原动作表情。动作切入时保留上一眼神用于过渡，返回站立后从自然回正平滑重新追踪；当前姿态和过渡快照使用独立眼纹理，防止快速连续切换时互相覆盖。
- 鼠标检测复用现有刷新计时器，熄屏、不可见、拖动或特殊动作期间不采集新坐标，不重置任何待机计时器。不保存位置数据、不联网、不使用全局钩子或独立进程。
- 建议 8–12 个循环关键帧；循环首尾姿态必须兼容。

### `idle_1`（带序号待机动画1）

- 每累计亮屏使用 60 秒触发一次，完整动作固定为 1.5 秒；不计入五分钟默认舔爪的完成次数。
- 先按桌宠当前位置计算互动气泡若此刻打开应出现在哪一侧，再选择相反方向的前爪：气泡预计在右侧则伸左爪，气泡预计在左侧则伸右爪。
- 时间线：坐下并伸出指定前爪 → 头部转向爪子、双眼眯成微笑弧线、嘴张开 → 短粉舌接触并舔舐爪面，头部、手腕和毛发高光有细小变化 → 收回舌头、嘴开始闭合、前爪降低并恢复普通姿态。
- 左右爪动作必须分别绘制，并保持屏幕左侧橘色、屏幕右侧黑色的原型脸部毛色位置，禁止通过镜像交换角色身份特征。
- 抬起的前爪更亮并位于前景；支撑前爪与远侧肢体略暗，保证舔爪的立体层次。
- 所有带序号待机均为低优先级。与默认五分钟舔爪或第六次特殊睡眠同时到点时，本次带序号待机被消费并取消；若高优先级动作在其播放期间到点，则立即中断并切换，之后不得补播被顶替的动作。

### `drag`

- 鼠标位移决定播放相位，鼠标移动得越快，脚步循环越快；停止拖动立即回到站立。
- 横向位移决定朝向：身体、头部、耳朵、鼻口和视线统一朝移动方向；左右步态分别加载 `drag_side/open` 与 `drag_side/left_open`。严格侧身朝右可见原色眼，朝左可见淡蓝眼，禁止直接镜像造成眼色交换；禁止正面身体在桌面上侧滑。
- 四条腿都必须真实参与：左前与右后为一组，右前与左后为一组，前后交替迈步。
- 后腿略暗、被身体轻微遮挡，前腿边缘与毛发高光更亮；身体随步态有轻微重心转移和上下起伏。
- 头部跟随身体朝向并随肩部步态轻微反向补偿，不能只翻转身体而让脸仍朝正面。
- 眨眼节奏独立于脚步循环；每约 3.6 秒自然闭眼约 0.17 秒，闭眼时保持当前四肢步态帧，避免脚步突然冻结或跳帧。
- 正式素材至少包含接触、下沉、经过、抬起四类步态节点，以及每个节点对应的闭眼版本。
- 开始拖动时先按实际横向位移选择 `drag_transition/right` 或 `drag_transition/left`，在 0.28 秒内完成正面站立、头肩转向、三分之四转身、侧身接触姿势；左右必须独立绘制以保留不对称花纹。
- 松开鼠标后进入 `SettlingFromDrag`，在 0.28 秒内反向播放同组转身桥回到正面，再由短状态融合接入默认呼吸，禁止瞬时复位。

### `lick`

- 总时长固定 2 秒。
- 时间线：站立转坐下 → 伸出一只前爪 → 头部朝爪子倾斜 → 眼睛柔和闭合或半闭 → 嘴张开 → 舌头伸出并舔爪 → 舌头收回、嘴闭合 → 回到正面站立。
- 必须清楚体现头部、双眼、嘴、舌头、被舔前爪和支撑前爪的形态变化。
- 建议 10–16 个精细关键帧。

### `FeedingFish`（喂它鱼）

- 右键互动气泡在清醒状态显示“喂它鱼”。气泡在左侧或右侧都使用完全相同的中央下降路径，不再选择方向前爪，也不得镜像猫咪或交换异瞳和脸部花纹。
- 完整时长固定 5.2 秒：普通站立 → 透明像素鱼由细线从头顶直接垂向真实嘴部，并在接近期间从展示尺寸平滑调整到约 0.46 倍的进食尺寸 → 原有 W 形嘴唇从进度 0.46 起自然分开 → 鱼头在进度 0.52 抵达唇线并咬断吊线 → 上端线与鱼上方短线在 0.09 进度内回缩淡出 → 固定大小、头朝下的鱼从进度 0.52 到 0.82 连续穿过唇线 → 最后一小截鱼尾进入后嘴巴于进度 0.88 前自然闭合 → 普通站立。
- 吞咽过程禁止用鱼的整体等比缩小模拟消失。鱼头接触嘴唇后，鱼的比例必须保持 0.46，仅通过中心位置向下移动表现进入；渲染裁剪由“上唇以上的完整外部区域”和“嘴唇内部的小椭圆入口”组成，进入口腔的鱼身被嘴部遮挡，嘴外剩余鱼身继续可见。嘴唇必须最后绘制在鱼的上层，形成包住鱼身的遮挡关系。只有最后 0.02 进度允许为抗锯齿收尾而淡出。
- 口腔最大半宽约 4.0 像素、最大半高约 2.25 像素，禁止恢复成大黑椭圆。上唇由左右两条曲线保留自然 W 形，下唇弧线随开口量移动；鱼尾逐渐变窄时，开口量从 1 连续降到约 0.35，再缓动闭合，不能突然跳帧。
- 鱼出现以后，猫咪只允许增加“嘴巴张开—吃鱼—闭合”这一项变化。整个 `FeedingFish` 状态必须持续使用 `Stand` 的中性开眼图层；禁止调用摸摸回应帧、前爪帧、闭眼帧、方向目光、头部歪斜、微笑嘴角、咀嚼脉冲、舌头、尾巴旋转或任何其他猫咪动作层。默认轻微呼吸可以保留，因为它属于原始站立状态而非喂鱼表演。
- 鱼道具使用 `assets/ui/feeding/fish-v1-imagegen.png`，保留真实透明 Alpha、像素鳞片、眼睛、鳃线和完整鱼鳍。吊线必须运行时绘制，不能烘焙进鱼素材；断线后不能遗留悬空长线、短线或鱼的残影。
- 动作进度 0 和 1 必须与相同呼吸相位的 `Stand` 逐像素一致；进入状态使用 0.24 秒、返回站立使用 0.32 秒共享缓动。由于动作中不再切换整猫关键帧，任何中间进度都不得出现双重猫影。
- 播放期间鼠标目光跟随、拖动、摸摸、重复喂鱼、哄睡和所有定时待机均不得覆盖动作。定时节点仍按全局规则消费，不排队补播；算数保持 UI 独立。睡眠状态隐藏此选项，先“叫醒它”后才能喂鱼。

### `sleep_transition`

- 总时长固定 2 秒，速度正常，但身体逐步趴下的过程要有足够形态细节。
- 时间线：头与肩降低 → 前腿折叠 → 腹部接近地面 → 后腿收拢 → 身体蜷缩 → 尾巴绕到身体前方并包住身体 → 双眼完全闭合。
- 结束帧必须能无缝衔接 `sleep`；程序会在右上方叠加跟随状态的 `Zzz`。
- 建议 12–18 个关键帧。

### `sleep`

- 身体蜷缩、尾巴包裹身体、双眼闭合。
- 仅保留非常轻的呼吸和毛发高光变化，不能出现醒来的眼神。
- 建议 6–10 个循环关键帧。

### `wake`

- 总时长固定 2 秒，不可直接倒放入睡动画。
- 时间线：耳朵先轻动 → 眼睛缓慢睁开 → 尾巴松开 → 头部抬起 → 前腿伸展支撑 → 身体起身 → 恢复原型正面站立。
- 建议 12–18 个关键帧。
- 当前正式序列在低位伸展与完全站立之间加入 `001b-transition-v1.png` 半起身桥接帧，避免身体重心一次跨越过大。

### `pet`

- 被摸后互动气泡立即收起；猫咪根据气泡原来所在的左/右方向选择对应动作组。
- 头部向互动方向温柔歪斜，嘴巴张开，露出一小段粉色舌头和嘴角两侧两颗对称的小猫牙；表情可爱，不得呈现攻击性。
- 与互动方向同侧的前爪抬起，轻轻朝另一侧挥动后挥回；另一只前爪和两只后爪保持身体支撑。
- 爱心由程序绘制在猫咪同侧旁边，整体约为旧气泡爱心的两倍；同侧稍下方绘制白色描边、黑色填充、31.25px 宋体“喵～”。
- 左右动作必须分别绘制并保持原猫不对称黑橘毛色位置，不能简单镜像脸部。
- 建议每个方向至少包含抬爪、挥出、挥回、收势四个关键帧。

## 生成与验收

正式制作时，原图的角色是“身份与外观参考图”，不是要求保留的背景。先生成一张高保真正面透明站立基准，再以该基准衍生每组动作关键帧。每完成一组都检查：角色身份一致、轮廓无漂移、眼睛数量和位置正确、四脚结构正确、尾巴连续、透明边缘干净、没有文字和水印。

程序按文件名读取关键帧，并依据本页“全局连贯性标准”进行状态缓动和相邻帧短融合。要进一步提高立体感，可以继续增加中间帧，不需要为每个动作重写状态切换逻辑。
